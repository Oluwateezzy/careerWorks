# Shared Schema Contract — Plugin ↔ Backend

> This document defines the exact data shapes that the Figma plugin produces and the backend expects.
> Both sides must agree on these contracts. Any change requires updating both the plugin and the backend schema validation.

---

## 1. Inventory Manifest (manifest.json)

The plugin produces a `manifest.json` file that conforms to the existing `figmaInventorySchema.js` v1.0.0 schema. This is the same schema the REST-based `figmaInventoryService.js` produced — the only difference is the **source** field indicates plugin origin.

### Top-Level Shape

```typescript
interface NormalizedInventory {
  schemaVersion: "1.0.0";
  
  source: {
    figmaUrl: "";                    // Empty string — no URL for plugin-sourced data
    fileKey: string;                 // From figma.root file metadata
    pageIds: string[];               // IDs of exported pages
    nodeIds: string[];               // IDs of exported root nodes
    version: string;                 // File version string
    fileName: string;                // Document name
    capturedAt: string;              // ISO 8601 timestamp
  };
  
  meta: {
    fileKey: string;
    name: string;
    version: string;
    lastModified: string | null;
    editorType: "figma";
    totalNodes: number;
    pagesCount: number;
    componentsCount: number;
    stylesCount: number;
    variablesCount: number;
  };
  
  pages: PageSummary[];
  rootNodeIds: string[];
  parentMap: Record<string, string | null>;    // nodeId → parentId
  nodes: Record<string, NormalizedNode>;       // nodeId → node data
  variables: ExtractedVariable[];
  styles: ExtractedStyle[];
  components: ComponentMetadata[];
  prototypeLinks: PrototypeLink[];
  renders: Record<string, RenderEntry>;        // nodeId → render info
  warnings: Warning[]; // Includes ASSET_BUDGET_EXCEEDED, SVG_EXPORT_FAILED, ASSET_UPLOAD_FAILED, etc.
  
  truncation: {
    isTruncated: boolean;                       // false for plugin (no truncation)
    truncationReason: string | null;
    truncatedCount: number;
  };
  
  // Plugin-specific additions (backend ignores unknown fields)
  pluginSource?: {
    pluginVersion: string;
    exportedBy: "figma-plugin";
    exportedAt: string;
  };
  
  prototypeFlows?: FlowStartingPoint[];         // Plugin-only: flow entry points
  assetManifest?: AssetManifestEntry[];          // Legacy v1: maps imageHash → S3 key
  assets?: AssetV2Entry[];                       // V2: classified assets array
  uploadReport?: {                              // Upload outcome report
    failedAssets?: { assetId: string; status?: number; error: string }[];
  };
}
```

## 2. Presign Upload Request / Response

### `POST /v1/projects/:projectId/plugin/presign-upload`

**Request Body:**
```typescript
interface PresignUploadRequest {
  files: {
    name: string;                        // e.g. "manifest.json" or "assets/abc123.png"
    contentType: string;                 // e.g. "application/json" or "image/png"
    sizeBytes: number;
  }[];
}
```

**Response Body:**
```typescript
interface PresignUploadResponse {
  status: true;
  data: {
    uploadId: string;                    // Unique upload session ID
    expiresAt: string;                   // ISO 8601 — when presigned URLs expire
    urls: {
      name: string;                      // Matches request file name
      presignedUrl: string;              // S3 presigned PUT URL
      s3Key: string;                     // Full S3 key for reference
    }[];
  };
  message: string;
}
```

**Validation Rules:**
- Max 500 files per request
- Max 100 MB total across all files
- Allowed content types: `application/json`, `image/png`, `image/jpeg`, `image/svg+xml`
- `manifest.json` must be in the file list

**S3 Key Pattern:**
```
projects/{projectId}/plugin-uploads/{uploadId}/{filename}
```

## 3. Complete Upload Request / Response

### `POST /v1/projects/:projectId/plugin/complete-upload`

**Request Body:**
```typescript
interface CompleteUploadRequest {
  uploadId: string;
  idempotencyKey?: string;
  failedAssets?: {
    assetId: string;
    status?: number;
    error: string;
  }[];
}
```

### 3.1 Asset Hashing, ID Strategy, and Upload Order
- **Asset ID Suffix:** The plugin sandbox generates stable FNV-1a hash suffixes `${kind}_${slug}_${fnv6}` so nodes can immediately and synchronously stamp `node.assetRef` and `fill.assetRef` during extraction without expensive DOM/AST traversals in the UI.
- **SHA-256 in UI Iframe:** When `EXPORT_ASSET` is posted from the sandbox to the UI iframe, the UI computes true 64-character SHA-256 via Web Crypto (`crypto.subtle.digest('SHA-256', data)`). It patches `asset.sha256` in `manifest.assets[]` and uses this SHA-256 for CAS deduplication (`/check-assets`).
- **Upload Order:**
  1. Presign files (`manifest.json` + `assetsToUpload`).
  2. Upload assets concurrently with 3 exponential backoff retry attempts.
  3. Write `uploadReport` (listing any `failedAssets`) and warning `ASSET_UPLOAD_FAILED` into `manifest.json`.
  4. Upload `manifest.json` to S3.
  5. Call `complete-upload { uploadId, failedAssets }`.
  6. The UI displays `"N assets failed to upload"` with a retry button if any asset failed.


**Response Body:**
```typescript
interface CompleteUploadResponse {
  status: true;
  data: {
    jobId: string;
    inventoryId: string;
    artifactId: string;
    s3Key: string;
    state: "ready-for-review";
    phase: "inventory_complete";
    counts: {
      totalNodes: number;
      pagesCount: number;
      componentsCount: number;
      stylesCount: number;
      variablesCount: number;
    };
    warnings: Warning[];
  };
  message: string;
}
```

**Backend Processing:**
1. Read `manifest.json` from `projects/{projectId}/plugin-uploads/{uploadId}/manifest.json`
2. Validate with `validateNormalizedInventory(manifest, { throwOnError: true })`
3. Create `FigmaInventory` record in DynamoDB
4. Create `PrototypeArtifact` record pointing to the S3 manifest
5. Create `PrototypeJob` with `state: READY_FOR_REVIEW`, `phase: INVENTORY_COMPLETE`
6. Return job/inventory metadata

## 4. Plugin Message Protocol (Sandbox ↔ UI)

```typescript
// Messages from UI → Sandbox
type UIToSandboxMessage =
  | { type: "START_EXPORT"; projectId: string; scope: ExportScope }
  | { type: "CANCEL" }
  | { type: "GET_FILE_INFO" }

// Messages from Sandbox → UI  
type SandboxToUIMessage =
  | { type: "FILE_INFO"; name: string; pageCount: number; nodeEstimate: number }
  | { type: "EXPORT_PROGRESS"; phase: ExportPhase; current: number; total: number; message?: string }
  | { type: "EXPORT_NODE_BATCH"; batch: SerializedNode[]; batchIndex: number; totalBatches: number }
  | { type: "EXPORT_ASSET"; hash: string; data: Uint8Array; format: string; sizeBytes: number }
  | { type: "EXPORT_MANIFEST"; manifest: NormalizedInventory }
  | { type: "EXPORT_ERROR"; error: string; phase: ExportPhase; recoverable: boolean }
  | { type: "EXPORT_COMPLETE" }

type ExportPhase = "walk" | "variables" | "styles" | "prototype" | "assets" | "assemble" | "validate";

interface ExportScope {
  pageIds?: string[];                    // Export only these pages (empty = all)
  nodeIds?: string[];                    // Export only these nodes (empty = all on selected pages)
  maxNodes?: number;                     // Safety limit (default: 10000)
  exportScale?: number;                  // Image export scale (default: 2)
  includeHidden?: boolean;               // Include hidden nodes (default: true)
  includePrototype?: boolean;            // Include prototype interactions (default: true)
}
```

## 5. Schema Versioning Strategy

| Version | Status | Description |
|:--------|:-------|:------------|
| `0.9.0` | Legacy | Pre-normalization raw format |
| `1.0.0` | **Current** | Normalized inventory with stable IDs, components list, prototype links |
| `1.1.0` | Planned | Plugin additions: `pluginSource`, `prototypeFlows`, `assetManifest`, text segments |

**Forward Compatibility Rule**: The backend accepts `1.0.0` inventories. Plugin-only fields (`pluginSource`, `prototypeFlows`, `assetManifest`) are in the `1.0.0` payload but are optional — the backend ignores fields it doesn't recognize. When the backend is updated to use these fields, bump to `1.1.0` and add them to `validateNormalizedInventory()`.

**Sharing the Schema**: Consider publishing `figmaInventorySchema.js` as a shared npm package (e.g., `@strata/inventory-schema`) that both the plugin and backend depend on. This ensures type parity and avoids schema drift.

## 6. Backend Validation on Receive

When the backend receives a plugin-uploaded manifest in `completePluginUpload`, it runs:

```javascript
const { validateNormalizedInventory, SCHEMA_VERSION } = require('./figmaInventorySchema');

// 1. Read manifest from S3
const manifest = JSON.parse(s3Body);

// 2. Schema validation
const validation = validateNormalizedInventory(manifest, { throwOnError: false });

if (!validation.valid) {
  return res.status(422).json({
    status: false,
    code: 'INVALID_INVENTORY_SCHEMA',
    message: 'Plugin-uploaded manifest failed schema validation',
    details: {
      errors: validation.errors,
      warnings: validation.warnings,
      schemaVersion: validation.schemaVersion,
    },
  });
}

// 3. Additional plugin-source checks
if (manifest.source?.figmaUrl && manifest.source.figmaUrl !== '') {
  // Plugin manifests should have empty figmaUrl
  // This is informational, not a rejection
}

// 4. Verify asset references
const assetManifest = manifest.assetManifest || [];
for (const asset of assetManifest) {
  const exists = await s3HeadObject({ bucket, key: asset.s3Key });
  if (!exists) {
    validation.warnings.push({
      code: 'ASSET_MISSING',
      message: `Referenced asset ${asset.hash} not found at ${asset.s3Key}`,
    });
  }
}
```
